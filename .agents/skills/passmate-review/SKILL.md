# PassMate 복습 검토

이 스킬은 구현·디버깅을 대체하지 않고 해당 작업의 검토 관점을 보탠다. 현재 요청의 범위와 이미 승인된 설계를 기준으로 필요한 부분만 확인한다.

## 원본 확인

저장소 루트의 `AGENTS.md`에서 관련 설계 경로를 확인한다. `docs/architecture/`의 `USER_FLOW.md`, `DATA_MODEL.md`, `API_CONTRACT.md`, `SCREEN_SPEC.md`가 원본이다. [제품 비전](../../../docs/PRODUCT_VISION.md), [제품 범위](../../../ARCHITECTURE.md)와 [검증 운영](../../../docs/AI_WORKFLOW.md)을 따른다. 정책을 여러 파일에 복사하지 않는다.

## 변경에 해당하는 질문

- 일정·기록: 제출 결과가 이력과 다음 일정에 함께 반영되는가? 저장 실패 시 DB 상태가 함께 복구되는가? 정책 변경을 이유로 기존 이력을 초기화하지 않는가?
- 삭제: 승인된 영구 삭제 범위의 하위 데이터와 기록만 삭제하는가? 부모 경로·사용자 소유 관계를 확인하고 중간 실패를 전체 롤백하는가?
- 복습 범위: 전체 복습과 세트 복습을 구분하는가? 기한·정렬·빈 목록과 없는/소유하지 않은 세트 오류를 유지하는가?
- 화면: 진입 시 목록, 결과 제출, 완료 안내가 같은 범위를 가리키는가? 조회뿐 아니라 제출의 늦은 성공·실패도 다른 범위의 상태를 바꾸지 않는가? 쿼리 전환을 검사할 때 전체 페이지 재로드만으로 검증하지 않는다.
- 권한: 로컬 프로필 ID에 대한 소유 관계 확인을 로그인 인증 검증으로 보고하지 않는가?

## 증거와 결정

기존 테스트를 먼저 확인하고 변경된 동작과 실패 경로에 맞는 검사만 실행한다. DB 원자성은 목 객체의 호출 순서만으로 입증하지 않는다. 화면 전환은 실제 사용자가 누르는 링크와 지연 응답으로 확인한다. 명령은 [검증 운영](../../../docs/AI_WORKFLOW.md)에 있다.

정책·DB·API·보안 변경은 `AGENTS.md`의 사용자 결정 경계를 따른다. 이미 승인된 정책의 국소 구현·오류 수정·검증에는 같은 승인을 다시 요구하지 않는다. 판단이 필요한 지점이 있어도 독립적으로 가능한 조사·테스트는 계속한다.

보고에는 실제 동작, 실행한 검증과 한계, 계약 문서 갱신 여부를 짧게 남긴다. 중요한 변경의 독립 검토는 사용자가 위임했거나 현재 실행 규칙이 허용할 때 요청한다. 작은 수정마다 별도 에이전트·새 문서·전체 테스트를 요구하지 않는다. 검토 결론만으로 커밋·push·병합 권한이 생기지 않는다.
