# PassMate 제품 비전

## 존재 이유

PassMate는 사용자가 암기해야 하는 개념을 **장기적으로 기억하도록 돕는 개인 학습 도우미**다.

다양한 공부법을 모아 제공하는 것이 목적이 아니다. 사용자가 무엇을 언제 다시 떠올려야 하는지 판단하고, 복습을 통해 기억을 유지하도록 돕는 것이 목적이다.

## 핵심 가치

1. **학습 자료는 사용자 중심**: 사용자가 기억할 개념을 학습 세트(Material)에 저장한다.
2. **능동적 회상 우선**: 정답을 보기 전에 스스로 떠올리게 한다.
3. **적절한 시점의 반복 복습**: 복습 이력과 회상 결과를 근거로 다음 복습 시점을 조정한다.
4. **복잡성 최소화**: 학습자는 복습 계획을 직접 관리하지 않고 오늘 할 일을 쉽게 확인한다.
5. **효과 검증 우선**: 기능의 개수보다 실제 복습 흐름의 완결성과 기억 유지에 기여하는지를 우선한다.

망각곡선은 복습 필요성을 설명하는 개념이지, 모든 사용자에게 동일하게 적용할 고정 시간표가 아니다. 실제 간격은 복습 결과와 선택한 알고리즘에 따라 결정하며, 특정 간격의 학습 효과를 근거 없이 단정하지 않는다.

## 제품의 중심 구조

```text
학습 자료(Material)
  → 암기 단위(FlashCard)
  → 능동적 회상 및 결과 기록(ReviewHistory)
  → 다음 복습 시점 계산
  → 오늘의 복습
```

- FlashCard는 Material에서 파생된다.
- ReviewHistory는 회상 결과를 보존하는 기록이다.
- 현재 카드의 복습 상태와 과거 이력은 개념적으로 구분한다.
- 학습 방식이 늘어나도 사용자에게 일관된 복습 경험을 제공한다.
- 서로 다른 학습 방식의 결과를 동일한 기억 점수로 취급하려면 별도 검증이 필요하다.

## 기능 추가 판단 기준

새로운 공부법, AI 기능, 화면을 추가하기 전에 다음을 확인한다.

1. 사용자의 장기 기억 유지에 직접 기여하는가?
2. 기존 학습 자료와 복습 흐름을 재사용하거나 자연스럽게 연결하는가?
3. 사용자가 학습을 시작하기까지 불필요한 단계를 늘리지 않는가?
4. 결과를 측정하거나 작은 실험으로 검증할 수 있는가?
5. 유지보수 비용과 복잡성에 비해 얻는 가치가 충분한가?

이 기준을 만족하지 못하는 기능은 도입을 보류한다. 새 학습법을 추가하기 위해 별도의 진도·복습 체계를 중복 구축하지 않는다.

## 단계별 방향 (제안 로드맵)

### MVP1 — 기본 복습 흐름 완성
- 폴더 → 학습 세트 → 카드 생성
- 카드 앞면 확인 → 스스로 회상 → 정답 공개 → 다시/어려움/좋음/쉬움 평가
- ReviewHistory 저장 및 단순한 다음 복습일 계산
- 카드 생성부터 다음 복습까지 종단 간 검증

### MVP2 — 복습 엔진 고도화
- 기존 기록을 활용하는 간격 반복 알고리즘 검토 및 도입
- 카드별 복습 상태, 기한 경과, 취약 개념 처리
- 복습 정책의 테스트·평가·변경 가능성 확보

### MVP3 — 회상 방식 확장
- 단답형 회상, 개념 설명, 연습시험 등 필요성이 확인된 방식만 점진적으로 추가
- 학습 방식별 차이를 보존하면서 공통 복습 경험에 연결

### 이후 — AI 개인화
- 카드 생성 보조, 취약 개념 분석, 복습 제안
- AI는 학습자의 기억을 확인하는 복습 과정을 대체하지 않는다.

이 단계 구분은 제품 방향에 대한 제안이며, MVP2 이후 범위가 확정되었다는 뜻은 아니다. MVP1의 확정 범위는 ARCHITECTURE.md를 따른다.

## 문서 운영 원칙

- 이 문서는 제품의 **목적과 기능 도입 판단 기준**에 대한 원본 문서다.
- MVP 범위와 도메인 관계는 `ARCHITECTURE.md`가 원본이다.
- 사용자 흐름·화면·ERD·API의 상세 설계는 현재 `docs/architecture/` 문서를 참조한다.
- 같은 정책을 여러 파일에 복사하지 않고 원본 문서로 링크한다.
- 설계와 구현이 충돌하면 임의로 정리하지 않고 차이를 확인해 사용자에게 알린다.
